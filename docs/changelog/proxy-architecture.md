# docs/proxy-architecture.md — 核对流水归档

> 本文件是 `docs/proxy-architecture.md` 顶部「最后核对」流水的冷归档（2026-10-05 剥离）。内容为历史变更记录，项目事实以正文当前态为准；日常阅读与 AI 加载无需读取本文件。新变更的过程叙述按时间序**追加到本文件顶部**（最新在上）。

> **最后核对（2026-10-01，jethub 桥接 Provider 与三个可选增强接口）：** Free Hub（Jet Hub 移植）经 `APIType="jethub"` 动态 Provider 接入转发链路。`forwardUpstream` jethub 分支：发送前回调注入的 `RequestAugmenter`（改写头基/体），可选 `RequestCustomizer`（qoder 族——返回 WASM 决定的完整出站 URL + 加密体，空 URL 回退默认构造）、响应侧 `ResponseInterceptor`（响应到达客户端前 peek 首帧分类：排队→`upstreamerr.QueueRetryError` 同 Key 等待重发（10s×180）、计费→`BillingLockError` per-model 锁后切号；或返回信封剥离 reader 替换 `resp.Body`）。跨边界错误类型在 `internal/upstreamerr`（proxy 不 import jethub——AGENTS.md 红线）。详见 §7.1a 与 `docs/jethub-architecture.md` §4–§5、`internal/proxy/interfaces.go`、`forward_retry.go`（`maxQueueAttempts=180`）。回归：`internal/proxy/customizer_test.go` + `augmenter_test.go` + jethub 侧 33 个适配单测。

> **最后核对（2026-09-22，响应身份头统一为 `setUpstreamIdentityHeaders` + 新增 `X-TinyLab-Request-Id`）：** 流式/非流式/Responses→Chat 翻译三条响应路径此前各自内联 `X-TinyLab-Provider`/`X-TinyLab-Key`，非流式 Responses→Chat（`passThroughResponsesAsChat`）还漏设这两个头。现统一为 `stream.go::setUpstreamIdentityHeaders(w, sel, reqID)`，并在 `reqID != ""` 时附带 **`X-TinyLab-Request-Id`**——把响应关联到该请求的 usage/monitor 条目（Playground 响应气泡据此绑定详情弹窗与 ttft/gt/in/res/ct/spd 指标，见 `playground-architecture.md` §6.3）。调用点：`streamResponse`、`passThroughResponse`（image/JSON 两分支）、`streamResponsesAsChat`、`passThroughResponsesAsChat`；`api/router_proxy.go` 的 CORS `Expose-Headers` 同步追加该头。回归：`internal/proxy/identity_header_test.go`。

> **最后核对（2026-10-02，失败响应身份头补齐 + 无可用 key 可见化 + Trace 驱逐一致性 + [DONE] 后强制收尾）：** (1) **失败路径身份头**：此前 `X-TinyLab-Request-Id` 只在成功流/成功透传路径写出——上游 4xx pass-through（`retry.go::handleUpstreamError` 的 `ActionPassThrough` 分支只写 Content-Type）与代理本地 `writeError`（502 all-keys-exhausted、503 queue-timeout/retry-limit、500 marshal）都不带头，Playground 气泡因此拿不到 `msg.reqId`，失败请求的 ⓘ 详情弹窗不可达（实测 400/502 响应头无任何 `X-TinyLab-*`）。现新增 `forward.go::writeProxyError(w, reqID, sel, status, msg)`（`sel` 可为 nil，仅写 Request-Id；非 nil 时走 `setUpstreamIdentityHeaders`），`forward_request.go`/`forward_combo.go`（fallback/greedy-squirrel 记录最后一个 target 的 reqID）/`forward_retry.go`（503/500 分支）调用点切换，`forwardWithRetry` 失败返回 `(false, reqID)` 而非空串；pass-through 分支补 `setUpstreamIdentityHeaders`。(2) **无可用 key 可见化**：`recorder.go::recordNoKeyFailure(id, providerName, model, errMsg, reqHeaders, sessionKey)` 为该终态失败写 usage 条目（无 key 身份，`Source` 分流 playground → pg ring）+ `request-done` 广播——此前这类请求在 Monitor/Playground 完全不可见（`recordUsage` 需要 `sel`，无 key 无法调用）。(3) **Trace 驱逐一致性**：`request_log.go::SweepTracesOnce` 删除 req 文件（按天或磁盘上限）后经 `purgeIndexLines` 重写受影响 `index-*.jsonl`（`filterIndexFile` 流式过滤 + `fsutil.AtomicWrite`，坏行保留，无变化不重写；孤儿行 reconcile：详情文件缺失且行 `ts` 早于 `traceIndexReconcileGrace`=10min 也清理），消除 Log Reader 里详情文件已不存在却仍列出的幽灵行。(4) **[DONE] 后强制收尾（用户实测：回复完成后 GT 仍计数、SPD 按 tokens/gt 衰减）**：`[DONE]` 是协议终态，但部分网关发出后不关 socket，`streamResponse` 读循环只在上游 EOF 才退出 → `recordUsage`（与冻结 GT/SPD 的 `request-done`）被拖到上游超时；现 `noteChunk` 见 `[DONE]` 即 `armDoneClose()`（`time.AfterFunc(streamDoneGrace=500ms, resp.Body.Close)`），最多再读 500ms 强制收尾，正常即关的上游不受影响。回归：`identity_header_test.go::TestFailurePathIdentityHeaders`/`TestRecordNoKeyFailure`、`request_log_sweep_test.go`、`stream_e2e_test.go::TestStreamResponse_DoneClosesLingeringUpstream`。

> **最后核对（2026-09-05，RES=enc 哨兵 + delta/done 去重）：** 密文 reasoning（Responses `encrypted_content`，如 muse-spark 类模型）无明文可计，RES 恒 0 无法区分"无推理"与"有但不可见"；Responses 终态 `output_item.done`/`completed` 回带全文经 `"text":"` 又计一次，CT 约翻倍。(1) **enc 哨兵**——`stream_usage.go` 新增 `reasoningEncryptedSentinel=-1` + `sseHasEncryptedReasoning`（非空 `encrypted_content` 触发）+ `applyReasoningSentinel`（明文永远覆盖）+ `splitOutputTotal`（哨兵归零）；`stream.go`/`responses_translate.go` 双分支检测 + ticker/终态接哨兵；`UpdateTokensSplit` 哨兵只粘 0、明文覆盖、无信息 0 不清 enc；前端 `monitor_state.js` 新增 `resIsEnc/resNum/resDisplay`，RES 格渲染 `enc`，OUT/SPD 归零参与；merge/live-patch/tick 三处单调全部哨兵感知。(2) **delta+done 去重**——`countContentSplit` 对 native Responses 非 `*.delta` 事件直接归零（`isResponsesDeltaEvent` 判 `.delta"`）；纯透传的 delta 行不受影响，混合流 translated-first 规则不变。(3) 测试：`TestSSEHasEncryptedReasoning` + `TestCountContentSplit_NativeDoneEchoSuppressed` + `TestStreamResponse_EncryptedReasoningSentinel`（RES=-1、CT 单计、OUT==CT），全量 proxy/usage suite + vet + 4 个 monitor JS `node --check` 通过。

> **最后核对（2026-09-05，Recent Requests 11 列：OUT 拆 RES/CT + GT 跳变根治）：** 用户实测：llama 推理流增量全在 `reasoning_content`（`content:null` 直到正文），Responses 原生增量是顶层 `"delta":"..."`——旧 marker 两者全漏致 live OUT=0；GT 反复跳另有独立根因。(1) **RES/CT 分流**——`usage.Entry` 加 `ReasoningTokens/ContentTokens`；`sseContentLength` 加 `"delta":"`（Responses output_text），新增 `sseReasoningLength` 认 `reasoning_content/reasoning/reasoning_text`（与 CT 互斥，单测隔离）；`stream.go` 双分支计数 + `reasoningCharsTotal` atomic + ticker `effRes/effCt` + 终态 split；`responses_translate.go` 把 reasoning summary 折成 `reasoning_content` chat chunk 再统一计数；`recordUsage` 可变尾参 `split...`（~20 老调用点零改动）；`broadcastTokensSplit` + `UpdateTokensSplit`（单调）；前端 OUT 格→RES/CT 两格，Spd=`(RES+CT)/GT`，colspan 10→11，aggregate-only 事件 delta 归 CT。(2) **GT 跳变根治**——`EntryTracker.Refresh` 改写 `Timestamp`（请求起始）是真凶：每秒把 GT 锚点 `ts+ttft` 后移致回跳。改 `lastActive` 独立心跳 map，Timestamp 永不动；`SweepStale` 判心跳（旧 stale 测试改心跳语义）；fcm 锚点优先级保留（reasoning 即起算）。(3) 测试：RES/CT 隔离 + 推理流终态 `OUT=RES+CT` + Refresh 不动 Timestamp 三用例，全量 proxy  suite 通过。

> **最后核对（2026-08-31，Round-2 P0-02/P1-01/P1-03/P1-04/P2-01 流式用量/SSE/Quota）：** (1) **token 原子化 + 时间驱动广播**——`stream.go` `inputTokens`/`outputTokens`/`contentCharsTotal` 改 `atomic.Int64`（stream.go:63-65），新增 250ms `time.Ticker` goroutine 在计数变化时推送 `request-tokens`（替代原 1500ms read-batch 节流，消除上游静默期盲区，stream.go:67-107）；OpenAI/Anthropic usage 提取改**条件赋值**（`if in>0`/`if out>0`，output-only usage 不再把 `inputTokens` 清零，stream.go:199-215/277-292/375-390）；终态 `recordUsage` 前 `outputTokens==0 && contentCharsTotal>0` 时补 `contentCharsTotal/4` fallback（stream.go:465-467）。(2) **include_usage 渐进推广**——`forward_retry.go` 对 OpenAI 流式默认注入 `stream_options.include_usage`（局部 `injectedStreamOpts`，forward_retry.go:46-60），上游 400/422 拒绝时 strip 后重试一次（`streamOptsStripped`，forward_retry.go:251-262）。(3) **SSE version**——`api/sse/register.go` `streamUsageEvents` 每推送附加单调 `seq` version（`appendVersion`），前端 `monitor_io.js` 检测 gap 触发补偿拉取。(4) **getQuotas 内联 keyDetail**——`api/monitor/register.go` 重构 `buildModelKeys`（复用 `getModelKeys` 逻辑），`getQuotas` 内联每 key latency/avgSpeed，消前端 N+1。
